Цель
Переписать метод run() в классе RabbitConsumer. Убрать динамическую регистрацию подписчика внутри функции и добавить аргументы Dead Letter Exchange (DLX) для основной очереди, чтобы механизм ретраев и DLQ работал корректно.

📋 Контекст
Сейчас в run() подписчик регистрируется через декоратор над локальной функцией. Это работает, но не является идиоматичным для FastStream и может вызвать проблемы при перезапуске. Кроме того, основная очередь создается без аргументов DLX, поэтому при reject сообщения не будут уходить в DLQ.

🛠️ Задачи (Что нужно сделать)
Шаг 1: Добавить аргументы DLX в RabbitQueue
В методе run() при создании RabbitQueue для основной очереди (payments.new) укажи аргументы:

x-dead-letter-exchange: "" (использовать дефолтный exchange).

x-dead-letter-routing-key: self._config.dlq_name (маршрут в DLQ).

Это гарантирует, что если сообщение будет отклонено (nack без requeue), оно попадет в DLQ.

Шаг 2: Исправить регистрацию подписчика
Вместо декоратора над локальной функцией используй явный вызов self._broker.subscriber(queue)(handler).

Создай локальную функцию handler(body, message).

Внутри неё вызывай await self.consume(body, message).

Зарегистрируй её через self._broker.subscriber(queue)(handler).

Шаг 3: Обработать CancelledError
Убедись, что при отмене задачи (например, при остановке контейнера) брокер корректно закрывается. Для этого в блоке finally вызови await self._broker.stop().

Шаг 4: Убрать лишние импорты и код
Убедись, что в файле нет неиспользуемых импортов (например, Depends, asyncio.Future). Оставь только то, что реально используется.

✅ Критерии завершения (Acceptance Criteria)
В run() основная очередь создается с аргументами x-dead-letter-exchange и x-dead-letter-routing-key.

Подписчик регистрируется через self._broker.subscriber(queue)(handler), а не через декоратор над вложенной функцией.

В блоке finally вызывается await self._broker.stop().

Consumer запускается и слушает очередь.

При ошибке обработки (например, PermanentError) сообщение уходит в DLQ (проверяется через веб-интерфейс RabbitMQ на порту 15672).
